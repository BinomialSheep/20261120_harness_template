# 検証記録 — AHC Thin Harness v0.1.0

作成日：2026-11-17。これはAHC公式問題を用いた性能評価ではなく、**同梱の独立した合成問題**によるオフラインの動作確認。

## 機能テスト

- 機能追加前の14件からなる完全テストスイートは**14件すべて合格**（約31秒）。
- 後から追加した「初期bestなしのAラウンド」「手動で提出した不正ソルバーの拒否」も独立に確認。16件のスイート全体は実行環境のタイムアウトで最後まで完了した確証が得られていないため、**16件の全件合格とは記載しない**。
- 合成Aラウンド：**10worker**の独立ディレクトリ、親コード・問題文・ツールの配布、成果コード保存、重複コードのsha判定、同じseedの採点、ベスト更新を確認。
- 合成Bラウンド：1worker、前roundから異なるseed領域、現行bestと同一seedでの比較。改善のない候補のpromote拒否を確認。
- seed0チェック：workerは許可されたdebug seed以外では`quickcheck.py`を実行できない。オーケストレーター側も全候補のseed0を再チェック。
- 全候補無効／tester変更／source変更／重複スコアの再利用／checkpointの一部としてのCSV再読み出しが少なくとも個別経路で動くことを確認。

## 重要な未検証事項

- 本物のAHC公式ジェネレータ・ジャッジ/対話型testerとの接続。問題ごとのadapterが必要。
- 1000ケースに固定した全10候補の実問題採点（合成デモは5ケース。`config.example.json`は本番1000）。
- Claude Code／Codexの実CLIを用いた10並列API呼び出し、承認・認証・料金・プロバイダ枠。コマンド例とworker並列化の仕組みはあるが、模擬agentで検証。
- OS級のworker隔離、GPU/CPUハード制限、外部へdetachした子孫の停止保証。
- 評価セットに対する繰返し選択バイアスの補正、別seedや実ジャッジでの一般化保証。

## セットアップ先での動作確認

```sh
python3 -m thin.cli demo
python3 -m unittest discover -s tests -v
```

通常の`config.json`には大会ごとの公式tool adapterを接続する。このテストに通ることは公式AHCでの有効性や参加条件への適合の保証ではない。
