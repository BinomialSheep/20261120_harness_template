# 制限、再現性、安全性

- **ローカルの軽量ハーネス**であり、公式AHC全問題に接続済みという意味ではない。各問題の公式generator/testerのビルド・スコアの向きと変換・インタラクティブ通信を`judge.command`の問題固有adapterへ接続する。
- **10 workerの同時実行**を要求するが、CPUコア/GPUのハードなcgroup制限、クラウドAPIの同時実行制限・クォータ・料金、LLM CLIのバージョン差を自動調整する機構はない。スレッド数を抑え、並列採点を2程度に絞る。仕事の有無はマシンのプロセスでも確認する。
- workerへ履歴をコピーしないが、ソルバーやエージェントが悪意を持って他ディレクトリへアクセスできないことは保証しない。`codex --sandbox workspace-write`等の機能はCLI側に依存。Claudeのアクセス許可や無人実行は実環境で確認する。OSセキュリティを強めたい場合は、別のcontainer/sandboxを追加する。
- subprocess timeoutは通常のプロセスgroupを停止するが、脱退した子プロセス、OSを越えるrunner、外部クラウドの継続課金を完全に停止できる機構ではない。
- コード生成成功率・CLI利用枠・LLMの推論コストを最適化するメタルーターは**未実装**。次のA/Bはオーケストレーターが選び、最良候補の採否も明示する。
- 1000seedは探索中の**開発評価**。10候補の最高点に過適合する可能性がある。独立本番分布、同じスコアの公式サーバー受理、データ利用規定の適合は保証しない。
- raw scoreは問題ごとにスケールが違うことがある。差分平均を既定としているが、相対的な指標が適切な問題なら設定で変換する。`paired_log_ratio`はすべてのscoreが正であることが必要。
- コンパイル時のリンクライブラリ・CPU性能・ソルバー自身の乱数や時間依存挙動は、ソースやseedが同じでも完全再現とは限らない。評価の実装はSHAを使ってsource/toolの変更を検出するが、システム全体の再現性を保証するものではない。
- worker workspaceには公式ツールと親コードをコピーするので、大きな公式ツールがあるとディスク容量を使う。Rust `target`などのビルドキャッシュはコピーしない。adapterの依存はワークスペースごとに接続検証する。
- `runs/`と`best/`はGit管理外であり、**Git pushだけで研究やbestをバックアップできない**。必要なら別媒体へコピーする。認証情報や大会配布物の公開範囲にも注意する。
- 開催年度によるAI利用規則は、この雛形のコードに埋め込まない。**長期AHC With AI部門専用の用途宣言**にとどめ、必要な条件はその大会の開始時に人間が渡す。
- 自動提出や順位APIは実装していない。最終提出は人間が`best/main.cpp`の内容を確認して行う。
