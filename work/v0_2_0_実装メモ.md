## 決めたこと

- config は schema_version 2。`problem.dir`（既定 problem/）を丸ごとラウンドに凍結する。アダプタは `problem/score_case.py`（tools/ の外）。`{problem}` と `{tools}`（= {problem}/tools）を置換。公式ツールのビルド結果は `problem/bin/`。
- 評価：A は段階 [100,300,1000]。上位 keep_top 以外で「現best より z×SE 悪い」か「首位との対の差が z×SE 悪い」ものを落とす（reanalyze.py の race と同じ）。首位だけ未使用の confirm 件で現best と比べ直し、採否はその値（z ≥ skip_confirm_z なら省く）。B は段階なし・confirm なし。
- ラウンドの seed：start = first_seed + (n−1)×block。dev = [start, start+stages[-1])、confirm = その直後。
- TLE は solo で最大 tle_retries 回走らせ直す（1回でも通れば ok）。アダプタのエラー（JSON なし）は環境エラーとして評価を止める。baseline の無効も止める。
- `evaluate --restart`：evaluation/ を退避して採点し直す。
- 案の JSON：`common`、各案に `title`（必須、40字以内）、`kind`、`idea`、`parents`、任意で `engine`、`refs`。A は1〜10案。B・C は1案（--idea でも可）。B・C は親を複数・refs を渡せる。
- 行動 C：測定・診断。成果物は report.md と out/。評価なしで close できる。
- worker の作業場所はリポジトリの外（既定 `../<repo名>.workers/R0001/A01`）。終了時に作業場所を cwd とする残りのプロセスを止める。
- 途中終了：利用上限・通信断は `interrupted`（自動では提出しない）。`accept`・`rerun`・`fail` で処理。上限を見たら、まだ起動していない worker を起動しない。時間切れは通常どおり提出。
- engine は config で {argv, bin 候補, min_version}。案ごとに engine を選べる。
- `go R0001 [--background]`：worker → 評価をまとめて行う。background は runs/R/go.log に書き、status で見る。
- `close R0001 --note '...'`：RESEARCH_LOG のラウンド記録に1行足し、usage.json とレポートを作る（失敗しても close は成功）。
- usage：codex の待ち呼び出しは `wait` と空の `write_stdin` を数える。
- 出力は短い表、`--json` で全文。
- notes.md（変更点・構成・確かめられなかった点）を promote 時に best/notes.md へ写す。親の関数一覧と親どうしの差分を作業場所に置く。
- レポート：tools/report.py（例の make_report.py を一般化）。特徴量はアダプタが結果 JSON の `features` で返し、scores.csv の列に残す。帯は config の report.bands、無ければ三分位。盤面の描画は problem/view.js（無ければ公式 vis の HTML を埋める）。probe は tools/probe.py。
- thin/ の行数は 2,000 行程度まで（1,500 は超える見込み。補助は tools/ に出す）。
