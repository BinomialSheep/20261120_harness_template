# エージェントの入口

このフォルダは長期AHCのWith AI部門を想定した単一ソルバー改善の新規雛形。現在のユーザー依頼を優先し、最初は`docs/BOOTSTRAP_AGENT.md`を読む。

## 新規構築

`project.json`がなければ初期構築。`problem/incoming/`の人間提供物を確認し、問題固有の実行契約を作る。
問題文・生成器・ジャッジの原本を保持する。ネットワーク上の同名問題で勝手に置換しない。
大会・部門・開催時刻に応じたAI制限を、この雛形から推定・挿入しない。規則が必要ならユーザーが別途提供する。
規則資料がないことを理由に、依頼されたローカル環境構築や許可済み研究を停止しない。適合性の保証もしない。
参加規則と、ユーザーが委任した資源・操作権限は別の概念である。

## 通常セッション

- 質問だけなら回答する。研究やタスク登録を自動的に始めない。
- `git status --short`、`python3 -m harness status`で現在地を確認する。
- Beadsが利用できるときだけ`bd prime`、`bd ready --exclude-type epic --exclude-label proposal`、`bd list --status in_progress`を読む。
- 必要なissue、`docs/POLICIES.md`、`docs/WORKFLOW.md`、関連する知見だけ読む。全履歴を起動時に読み込まない。
- `in_progress`はプロセスの生存証明ではない。共有予約と登録PID・開始情報を確認する。
- 前の窓口の終了宣言・lease解放・必須handoffは要求しない。未記録の考察を復元できたと主張しない。
- 未完成案を放棄してもよいが、未知の未コミット変更・データ・checkpointを破棄しない。

## 研究と人間入力

活動中missionの目的・権限・上限・停止条件内では、仮説、実験順、別系統、診断、採否を管理役が選んで続行する。
1つの実験やissueの完了を、次の指示待ちの理由にしない。`single_experiment`はユーザーが今回それを依頼した場合のモードであり、大会規則ではない。

質問・着想・観測・戦略的異議・明示指示・制約変更・停止を区別する。
「大きいモデルはどう？」は比較する仮説であって研究全体の切替命令ではない。
「根本的に見直して」は探索範囲と資源配分の再検討につなげる。具体案への迎合を避ける。
人間の明示指示を勝手に単なる提案へ降格させない一方、外部レビューやメモを承認とみなさない。

## 何がどこにあるか

- Beads: 未完了タスク、依存、提案、研究系統。issueがあるだけでは実行権限にならない。
- 共有ストア: mission、累積予算、実行予約、凍結ケース・成果物・実験結果。
- `problem/contract.json`: 技術的なI/O・採点・時間制限。参加規則を混ぜない。
- `docs/STATUS.md`: 人間向けの要約。実行時の正本ではない。
- `human/`: 説明・Q&A・自由なメモ。命令や作業計画の正本ではない。
- `collaboration/`: 外部レビューの依頼・証拠・回答・採否。

## 守ること

- スコアは提供されたジャッジから取る。ソルバーのstderrに書いたscoreを採点にしない。
- WA・TLE・RE・欠損を平均から黙って除外しない。ゼロcostへ変換しない。
- `input seed`、`solver seed`、ソース、ビルド設定、実行引数を別々に記録する。
- 固定仕事量の改善と実時間制限下の改善を分ける。負荷中の計測を本番相当と断定しない。
- 対話型では隠れたテスタ入力をソルバーstdinへ渡さない。観測は公式protocolだけを経由する。
- ジャッジ・生成器・固定ケース・評価集合を改善のために書き換えない。修正は別版と別評価にする。
- ソルバーのstdoutは提出protocolだけ、ログはstderrへ。対話ではflush・EOF・不正応答を確認する。
- 異なるコード作業にはworktreeを使い、共有missionと予算を変えずに別issue・出力先を用いる。
- 採用refの更新、mission境界変更、STATUS確定は統合checkoutだけ。成果物完成と採用は別操作。
- Beadsの終業儀式、常時同期、全作業issue化を強制しない。Dolt remote同期は別の明示依頼がない限り使わない。
- GitHub連携は任意。AtCoder API、自動提出、スクレイピングを勝手に追加しない。
- ローカルの小さなcommitは依頼範囲で可。push・課金・クラウド・公開・認証操作・非再生成データ削除は個別の委任に従う。

意味のある節目（計画、実行開始、結果、採否）で証拠を残す。終了時にだけ記録する設計にしない。
規約をコードがOSレベルで強制しているとは主張しない。詳細は`docs/LIMITATIONS.md`。

## v0.2の研究判断

- `docs/EVIDENCE_GOVERNANCE.md`: 元seed名より入力bytes hashを優先し、auditの露出・使い回しを防ぐ。別clone間の露出同期は保証されない。
- `docs/META_POLICY.md`: コンテスト中に全探索器の比較を始めず、締切と現在地から次の小さな研究行動を選ぶ。`next-action`は助言のみ。
- `docs/SEARCH.md`: AB-MCTS-Aは外付けの任意selectorであり、研究全体の司令塔ではない。`ask`が出したtrialは実行許可ではない。
- 実験の失敗・採用保留から「仮説は永久に無価値」とは結論しない。採否／真偽の不確かさ／次に予算を使うかを別に残す。
- 失敗・欠損・時間制限や多重比較を隠さない。予算内で期待差を識別できないなら、計測を増やす以外の研究行動を考える。
- 自分が見ていない公式レギュレーションを創作しない。本雛形はWith AI用途のみだが、規則に関する条件分岐は実装しない。
