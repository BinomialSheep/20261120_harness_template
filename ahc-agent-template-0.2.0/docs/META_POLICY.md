# 締切を考慮した研究選択（v0.2の最小実装）

競技中に「どのハーネスが強いか」を毎回比較する時間はない。最初は**検証可能な決定的既定方策**を使い、普段の実験ログから後でメタ方策を改良する。現行の`harness.portfolio`は learned bandit ではない。

`research/next_action.example.json`を参照し、現在の事実と締切を記入する（勝手に大会締切を推測しない）。

```sh
python3 -m harness next-action --state research/next_action.json
```

優先順は、(1)確認・提出準備用の確保時間に到達→凍結と検証、(2)ジャッジ未検証→測定器修復、(3)合法baselineなし→baseline確保、(4)評価に重大な疑問→診断、(5)分散未較正→安価な較正、(6)局所改善が3回停滞→別系統、(7)それ以外→有力仮説の深化。

これは提案のみで、実行コマンド・権限・予算は発生しない。基準閾値の「3回」は最適性を主張しない置換可能な既定値。結果を収集できたら、将来は現在の状態と次の行動の効果をログ化し、Greedy・固定探索枠・AB-MCTS・メタ方策を時間切れ時点の最良スコアで比較する。選ばれなかった行動の反実仮想は通常観測できないので、履歴再生だけで因果的優越を主張しない。

最後に保証すべきなのは、生成した候補の数ではなく、**期限までに検証済みの最良提出候補が存在すること**である。
