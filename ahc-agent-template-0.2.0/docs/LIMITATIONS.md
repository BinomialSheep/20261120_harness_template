# 実装範囲と限界

## 実装済み

Linux/WSL、Python 3.11+標準ライブラリ、C++凍結、内容hash付きケース集合、生成器snapshot、非対話/対話/出力採点、対応比較、block bootstrap、ケースCSV、再実行、保存出力の再採点、任意の外部可視化コマンド、worktree共有状態、missionと累積予約、sealed evidence、Beads接続、選択的GitHub連携。

## 問題ごとに必要な作業

入力ジェネレータと採点器のビルド、wrapper、採点方向、制限時間、hidden input、対話タイムアウト、seed伝達、パラメータの提出形への固定。
`problem/contract.json`の初期値は実問題の仕様ではない。`verified=false`から始める。
固定の`Score =`パーサ、AtCoder API、非公式API、スクレイパ、自動提出はない。

## 保証しないもの

- 任意ソルバーの悪意を隔離するOS sandbox。評価プログラムも同一ユーザーでファイルを読める。hidden inputをprotocol外から読む攻撃まで防いでいない。
- 本番CPU/メモリ計測との完全一致。RLIMIT_ASはRSSではない。ピークメモリとCPU時間は未計測ならnull。
- 対話型の汎用1手時間監視。公式testerの契約を利用する。外側timeoutだけではsolver起因とtester起因を区別できない。
- 非常に大きな入力/出力の完全なstreamingパイプライン。生成器stdoutは指定上限まで保持し、文字入力を前提にする。
- 外部ランタイムや動的ライブラリまで含むビット再現性。hashで固定するのは明示したファイル。
- 実験途中の自動resume。部分runは残すが新runで再実行。生成失敗も部分データを保持し、暗黙に追記再開しない。
- 各ケースで本番と全く同じ行動列。wall-clock探索は負荷で変わる。
- CIの適応的選択補正、勝者の呪いの自動除去、公式最終順位の再現。
- 個別CPUコア/GPUの強制割当。機械単位の協調lockはあるが、外部プログラムは止められない。
- 常駐研究、セッション終了後の処理生存、別マシン間の予算排他。
- Gitだけによる共有DB/evidenceの完全backup。`backup`は研究stateだけで、Beadsとevidenceは別に必要。

## 統計の保守性

1件でも失敗があれば全体判定invalid。成功ケースの診断は残すが、それだけで優位とは判定しない。
これは公式の失敗スコアを再現した集計ではなく、不正な評価で勝ったと誤認しない既定の研究方針。
公式の集約式を追加する場合はvalidity/raw score/contest scoreを別フィールドにする。

## 非埋込みのレギュレーション

この雛形はAI使用の許可・禁止を判断しない。大会ごとの規則資料は任意のユーザー入力。
不明を禁止とみなさず、規則がないから適合性が保証されたとも言わない。
