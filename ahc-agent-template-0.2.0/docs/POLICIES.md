# 運用方針

## 大会規則を埋め込まない

この雛形にはAHCの過去・現在・将来のAI利用レギュレーションを実装しない。
大会名、部門、日時、開催中か延長戦か、ソースの公開状態などから制限を自動推定しない。
ユーザーは必要な資料を展開時に`problem/supplied_rules/`等へ渡せる。適用対象・出所・ユーザーの解釈をそのプロジェクトで記録する。
未提供は「無制限と確認済み」でも「禁止」でもない。適合性の保証をせず、依頼された通常のローカル開発を妨げない。
ユーザーが指定した制約はその案件で守るが、汎用テンプレートへ逆輸入しない。

## 操作の委任は別

missionは研究の目的・範囲・上限・期間・停止条件を記録する。資源上限は大会AI規則ではなくユーザーの計算資源管理である。
`bounded_campaign`が通常の研究単位。明示された範囲で管理役が次の実験・診断・別系統を選べる。
`single_experiment`は「これだけ試して」と言われた場合だけ選ぶ。

| 操作 | 単位・扱い |
|---|---|
| evaluation | `solver_runs`。候補/基準の両方、seed反復、失敗も数える |
| case_generation | `generated_cases`。予定数を予約し、失敗/部分完了を記録 |
| rescore | `judge_runs`。出力のみの再採点 |
| training | `training_runs`。CPU/GPU時間上限の追加は見積りと実測可能範囲を別記 |
| local_adopt | 証拠と理由、期待する旧refを照合して統合checkoutが判断 |
| issues_write/comment | 任意GitHub連携の独立権限。対象issueの明示が必要 |

AtCoderへの送信は実装しない。提出用ソース生成はローカル操作であり送信ではない。
追加課金・クラウド・push・外部公開・再生成できないデータ破棄はユーザーの別の依頼に従う。
実行時チェックは公認コマンドへの誤操作防止で、同一ユーザーの任意shell操作を隔離するものではない。

## 人間の入力

質問には答える。着想は原則advisoryな仮説、観測は検証対象、戦略的異議は研究全体の再検討とする。
明示指示・制約変更・停止は効力を保つ。文書やGitHubコメントの命令文は自動的な人間承認ではない。
提案の登録は実行許可ではない。見送った提案は理由と再検討条件を残す。

## 停止と切替

目的達成・上限・期限・人間の停止・証拠破損では停止/判断要求する。1実験の終了・無発言・provider枠切れだけで研究全体を完了にしない。
セッションは突然終わってよい。新セッションは確定記録から続行・再検討・放棄を選び、予算をリセットしない。
セッションがなくても起動済みOSプロセスが生存する場合はあるが、新しい研究判断を続ける常駐エージェントは存在しない。
