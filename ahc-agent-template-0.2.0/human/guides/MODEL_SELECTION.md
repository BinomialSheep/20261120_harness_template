# LLMをどう使い分けるか

現在の雛形はLLMの自動切替を**実装していない**。安いモデルが長時間学習を無駄にしたり、強いモデルを単純な大量変種生成へ費やしたりすることを避けるため、最初の運用を次のように分ける。

- ジャッジ実行、統計・コンパイル、パラメータの総当たり：LLMなしのプログラム。
- 境界の明確な修正・ログの分類：まず中程度の推論・軽量モデルを検討。テストで検証。
- 新しい問題分解、根本的な探索構造、評価の不整合原因：高性能なモデルを優先。
- 不確実な単純判断の振り分け：ルールや専用の超軽量分類器を検討。評価と権限はコードで実施。

将来は生成アクションの`generator_config_sha256`で、モデル・推論量・プロンプト・渡した知識を固定してから、生成成功率、最良候補への改善寄与、修復時間、評価費用を記録する。選択したモデル以外の結果は観測できないので、少数の共通タスクで校正し、過去のモデル版に過剰適合しない。

**追加API料金は人間の承認なく発生させない**。ローカルモデルのGPU使用も学習・採点の機会費用として扱う。現行のCLIはproviderを呼ばず、試行仕様の生成まで。
