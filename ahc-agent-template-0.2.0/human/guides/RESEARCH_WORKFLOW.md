# 研究を任せる・一緒に考える

人間は目的、価値基準、資源上限、大きな制約を決める。管理エージェントは範囲内で次に試す仮説と実装・評価を決める。

| 発言 | 扱い |
|---|---|
| 今どうなってる？ | STATUSと証拠から回答。実験を起動しない |
| 近傍をもっと増やしたら？ | 仮説として価値と機会損失を評価 |
| スコアが止まってない？ | 停滞・測定ノイズ・探索範囲を診断 |
| 根本的に違う方法も考えて | 現系統だけでなく別系統と診断へ再配分を検討 |
| この変更をNケース以内で試して | 明示範囲を実行。必要な権限不足だけを確認 |
| ここで止めて | 新規作業を停止。実行中ジョブの状態と安全な止め方を説明 |

研究はexploit（現系統の改良）、explore（別構造）、understand（失敗の解明）、maintain（基盤）に分けて見られる。
比率を固定の正解にせず、停滞や発見で変える。研究基盤の整備だけが目的化していないかも確認する。

人間は全エージェントのチャットを読まなくてよい。普段はSTATUSの目的・結果・方針変更・残予算・判断待ちを見る。
根拠を知りたいときだけrun/experiment/Beadsへ掘り下げる。外部レビューはcollaborationに残す。

失敗案は「この版・この予算・この入力では効かなかった」と残す。未来に条件が変わる余地をつぶさない。
