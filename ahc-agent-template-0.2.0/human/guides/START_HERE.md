# 最初にすること

## 1. コピーする

ZIPを解凍し、`ahc-agent-template-0.2.0`全体を新しい作業フォルダへコピーする。隠しファイルも含める。
既存リポジトリへ上書きせず、新規の問題用に使う。WSLのLinuxファイルシステム側でVS Codeを開く。
VS Code拡張で始めてよい。tmux、常駐エージェント、外部オーケストレータへの乗換えは不要。

最初に[今回増えた機能](NEW_IN_V020.md)も参照してください。

## 2. 資料を置く

`problem/incoming/`へ、問題文・入力生成器・ローカルジャッジ/テスタ・可視化器・サンプルを置く。
公式ツールがzipのままでもよい。元ファイルを消さず、エージェントに中身の役割を調べてもらう。
長期AHC・With AI部門での利用を想定しています。大会ごとに追加の参加条件など渡したい資料があれば`problem/supplied_rules/`へ。この雛形には特定大会のAI制限は入っていない。

## 3. エージェントへの依頼例

> このフォルダをAHCのこの問題用にセットアップしてください。問題文と公式配布物はproblem/incoming/に置きました。
> AGENTS.mdとdocs/BOOTSTRAP_AGENT.mdに従い、必要な環境、公式ツールとの接続、合法なbaseline、ケース生成、対応評価、使い方の資料まで整えてください。
> 大会ごとの追加条件が必要なときは、私が別途提供します。現在のレギュレーションを勝手にハードコードしないでください。
> 課金・公開・GitHubへの書込みなど、外部への影響があることだけまとめて確認してください。

GitHubを使うならリポジトリ名も伝える。AtCoderのログインやAPIキーは不要。

## 4. セットアップ完了を確認する

エージェントに、使った公式ツールの版、baselineの合法性、ケースとスコアの意味、対話型なら情報の境界、実行コマンド、未検証事項を報告してもらう。
[問題接続メモ](PROBLEM_ONBOARDING.md)が自分の問題の内容で埋まれば、再利用しやすい。
模擬問題のテスト成功だけを「このAHCで正しい」と読み替えない。

## 5. 改善研究を委任する

> この目的で改善研究を進めてください。評価は合計N回、入力生成はM件、期限は…です。手法は任せます。
> 現行系統の改善だけでなく、別の解法や失敗分析も検討してください。

数値は自分の予算で指定する。不要な単位は委任しなくてよい。エージェントは上限内で複数の実験を進める。
提出はこのハーネスから行わず、検証したソースを人間が別途扱う。

手で基盤だけ試すには、ルートで`python3 tools/test.py --strict --record`、`python3 tools/demo.py`。実問題の入力は変更しない。
