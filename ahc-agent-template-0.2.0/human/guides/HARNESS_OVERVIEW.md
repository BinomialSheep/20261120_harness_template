# ハーネス全体の解説

この基盤は「いい解法を自動で保証するもの」ではなく、**仮説を実装し、同じ条件で測り、結果と経緯を次のセッションへ残すもの**。

```text
人間の目的・予算・質問
        ↓
Claude Code / Codex（会話窓口・研究管理）
        ↓
Beadsの課題 → 仮説・実験計画 → ソルバー候補
                                ↓
         凍結入力 → 実行 → 公式ジャッジ → スコア/失敗/時間
                                ↓
        対応比較・診断 → 採用/保留/別系統 → 次の研究
```

## 五つの管理対象

**コード**はGit、実行する版はartifact ID。作業中の変更と実際に測ったものを混同しない。
**ケース**は生成seedだけでなく実際の入力bytesを固定する。公式ツールの更新で同じseedの意味が変わっても取り違えない。
**実験**は原案・途中変更・結果。成功後に最初の仮説を書き換えない。
**研究運用**はmission・予算・予約。並列セッションでも全体の残量を共有する。
**知識**は条件付きの知見と意思決定。スコアが上がった事実と、なぜ上がったかの仮説を分ける。

## AHCならではの部分

対戦相手と座席の代わりに、入力分布・ケース属性・ソルバーの乱数・時間予算が評価の中心。
1つの解答プログラムでも対話型はあり、ジャッジとの通信を扱う。
採点は最大化/最小化を明示し、公式順位表の相対スコアとは分離する。
CodinGameのAPIクライアントは入っていない。GitHub連携は協業用の任意機能で、大会APIではない。

## 自動化しないこと

人間の雑談を命令へ変えること、無断の提出・課金、規則の推定、悪い実験結果の隠蔽。
常駐してLLMを呼び続けるサービスもない。会話窓口が止まれば新しい研究判断は止まるが、開始済みOS処理が続く場合はある。
